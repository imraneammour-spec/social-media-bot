# OAuth General Keyword Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separate direct-message keyword automation from the legacy prompt-request delivery path without weakening account isolation, OAuth credential use, or durable job deduplication.

**Architecture:** Add an account-scoped delivery mode and explicitly configured message fields. `prompt_request` remains the migration default and retains the existing media extraction and prompt-link sequence. `direct_message` bypasses all prompt/media work and stores only explicitly configured general follow-up text in the existing durable follow-up job lifecycle.

**Tech Stack:** Python, Flask, SQLAlchemy, Alembic, unittest.

**Spec:** User-approved design in the 2026-09-04 conversation.

## Global Constraints

- Existing configurations default to `prompt_request`; no user-facing general copy is generated by backend code.
- General delivery requires configured nonempty private text; a general follow-up requires both enabled state and configured nonempty text.
- Preserve OAuth-only credential resolution, account/tenant scoping, event claims, durable follow-up leasing, and scheduler/Cron behavior.
- Do not alter production configuration, Railway variables, publishing, commits, pushes, or deployments.
